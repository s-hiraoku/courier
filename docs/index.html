Context Courier User Guide

A local-first CLI for structured handoffs between workspaces.

What It Does

Context Courier lets one local workspace leave actionable Markdown context in another local workspace's .courier/inbox. The receiver can list, read, acknowledge, and complete the handoff. The sender can later check the current status.

new acknowledged done

Install

npm install
npm run build

Core Workflow

cd /tmp/app-project
courier init
courier target add library-project /tmp/library-project
courier send --to library-project --title "Auth helper fails" "Token validation accepts empty strings."

cd /tmp/library-project
courier inbox
courier read <handoff-id>
courier ack <handoff-id> --note "I will inspect this."
courier done <handoff-id> --note "Fixed validation."

cd /tmp/app-project
courier sent
courier status <handoff-id>

Receiver Checks

The MVP does not run a daemon, watcher, notification service, or agent integration. The receiver explicitly checks handoffs with courier inbox. Future receiver detection is intentionally left open for design review.

Attachments

courier send --file <path> copies the source file into the target workspace under .courier/attachments/<handoff-id>/. Small text files under 100 KB are embedded in the Markdown handoff. Large or binary-looking files are copied but not embedded.

Safety

Courier writes only under .courier/ directories, except for reading source files passed to --file. It does not control terminals, automate agents, run target commands, contact network services, or implement MCP behavior.

Codex Harness

The repository includes a lightweight project harness adapted from s-hiraoku/codex-harnesses. Use npm run verify before finalizing changes. The harness provides scripts/verify.sh, scripts/checkpoint.sh, and a ledger/ for resumable task state, decisions, risks, and verification notes.

Project-Agnostic

Rig and Synapse are background context only. Rig is only an example target workspace. Context Courier is project-agnostic.
